# 系统提示词：临时文件纪律

模型反复落盘一次性脚本（探针、A/B 对比、测量日志、提交说明），是提示词里没有约束的
直接后果——原文只有一句「仅在脚本较长、需要复用或需要作为工件保留时，先落盘再执行」，
既没有给落点，也没有收尾要求。

## 加了什么

`src/main/agent/SystemPrompt.ts` 新增 694 字符的 `## 临时文件纪律`，位置在
「工具使用纪律」之后、「当前工作区」之前，每次请求都随系统提示词下发：

- **默认不产生文件**：一次性任务用 `python -c` / `node -e` / here-string / 管道完成
- **落点唯一**：项目根 `.tmp/`，且必须被 `.gitignore` 覆盖；已有 scratch 目录则沿用
- **一个任务一个文件**：覆盖而不是递增 `-v2` / `-final` / `-fix`
- **产物两分**：交付物给路径不删，中间产物任务结束删
- **收尾自检**：列文件 → 判类型 → 删中间产物 → `git status` 复核

## 为什么放在系统提示词

这条约束必须对每一轮生效，放在系统提示词里才能覆盖所有会话。代价是它进入请求头，
因此必须是**常量**：整段不含时间戳、会话 ID、绝对路径，保证 provider 的前缀缓存
不会因为这段文字发生变化而重算整个会话。`tests/prompt-scratch-discipline.test.js`
里有一条用例专门比对两次构建的字节一致性，并断言段内没有盘符路径。

## 配套

- `.gitignore` 增加 `/.tmp/`，让约定的落点本身不会进仓库。
- `tests/prompt-scratch-discipline.test.js` 7 条：内联优先、落点唯一、产物两分、
  收尾自检、段落位置、无常量漂移、未打开项目时同样存在。

## 验证

提示词相关回归 21/21，全量 **659/659**，`npm run build` exit 0。

已经落盘的会话不会改变历史消息，但下一轮请求就会带新段落——不需要重建数据库，
重启应用即可生效。
